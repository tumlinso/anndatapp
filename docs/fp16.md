# Dense binary16 storage

`anndatapp::Float16` is a two-byte, trivially copyable IEEE binary16 value.
`Array::empty<Float16>` and the existing dense borrowing and ownership
operations use `DType::float16`. Typed views expose `Float16` pointers and
strides. `from_bits` and `bits` access the exact stored representation.
`from_float` and `from_double` round to nearest with ties to even.
`to_float` and `to_double` widen explicitly. Numeric conversions canonicalize
NaNs, and dense copies preserve their stored payload bits.

H5AD stores the IEEE binary16 floating-point datatype. Zarr v2 uses the
byte-order-qualified `f2` dtype, and Zarr v3 uses `float16`. Eager reads and
writes, backed selections, and transfers into caller buffers use the ordinary
dense array APIs. File byte order is distinct from native memory byte order.
Dense arrays use the existing AnnData encodings, including within MuData and
TreeData. AnnDataSet can stack same-dtype dense FP16 components, and
SpatialData can use FP16 image raster levels.

The existing sparse, scalar, column, record, and spatial label dtype
contracts apply. FP16 CSR and CSC requests raise `unsupported_dtype`.
