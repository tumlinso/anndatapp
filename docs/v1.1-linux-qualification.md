# AnnData++ 1.1.0 Linux qualification

AnnData++ 1.1.0 adds the MuData, TreeData, AnnDataSet, and SpatialData modules
and the `import anndata;` facade. The storage and encoding boundaries are
documented in the [format-family guide](format-family.md).

AnnDataSet uses positional X reads by default. Set
`DatasetOptions::check_axis_names` to compare selected axis names across
components. Prepared CSR reads retain checked resources for repeat execution.

The HDF5 update reuses worker transfer machinery in ordinary backed reads.
It groups dense selections by compressed chunk, batches consecutive sparse
segments, and retains structural validation and caller-owned output.
AnnDataSet manifest copies resolve the original source after a working
directory change and reject a replaced source. Materialization constructs
AnnData with its real axis tables.

The CMake package reports version 1.1.0 and uses `SameMajorVersion` compatibility.
Consumers build module interfaces with their compatible toolchain. The internal
axis-table constructor changes a core module interface and causes a one-time
dependent module rebuild.

## Linux checks

The candidate was built on Linux x86-64 with Clang and clang-scan-deps 18.1.3,
CMake 3.28.3, and HDF5 1.10.10. The [qualification receipt](../tests/results/v1.1-linux.json)
binds the frozen build, source, and test inputs and the retained local evidence
under `build/release-1.1`.

| Gate | Passing checks |

| ASan/UBSan | 38 / 38 |
| Focused TSan | 4 / 4 |
| Core-only | 22 / 22 |
| HDF5-only | 32 / 32 |
| Zarr-only | 29 / 29 |
| Shared Debug, shared Release | 38 / 38 each |
| Format-family and Parquet interoperability | 54 / 54 |
| Shared Release with Parquet, focused installation and interoperability | 3 / 3 |

Installed consumers passed with `1.0` requests and with `1.1.0 EXACT`.
The exact request exercised both facade imports and a dependency-free core
consumer with five BMIs. The Parquet-enabled shared library resolved its
private Arrow and Parquet dependencies through its installed RUNPATH.

Separate reference runs passed Scanpy 1.11.5 record interoperability,
five HDF5 link cases, and legacy MuData 0.3.10 missing-axis H5MU and Zarr reads
followed by current-reader reopen. The full format-family suite exercised
legacy TreeData and SpatialData and SnapATAC2 fixtures with the Zstandard
HDF5 filter. Native sanitizer runs used ASan with leak detection disabled,
UBSan with halt-on-error, and the targeted TSan preset.

## Performance evidence

Four-worker streaming throughputs were 510.5 versus 80.3 MiB/s for
shard-aligned Zarr v3 and 4,216.5 versus 182.3 MiB/s for gzip CSR H5AD. The
comparisons use the same files and block requests, four physical cores, and
warm caches. Each reader passed an independent block oracle before timing.
The [streaming benchmark](../benchmarks/parallel_streaming/README.md) records
the Python APIs, worker setup, allocation differences, and one-worker controls.

The [HDF5 fix benchmark](../benchmarks/results/hdf5-read-reuse.json) compares
the changed production code with its immediate baseline. The code hashes
and all 128 passing process receipts were reverified during release
qualification.

The standard native suite compared v1.0.0 with the v1.1.0 candidate using the
same driver and fixtures. Both validated all 38 operations. The campaign
recorded 100 timing processes and 20 separate diagnostics. The single
investigation flag was the 512 × 512 in-memory CSC opposite-axis gather copy,
whose median rose from 0.233 to 0.295 ms. This bounded, checked sparse-copy
path was already present before the HDF5 reuse changes. Allocation counts
and bytes for the operation matched. The measured storage-backed opposite-axis
reads improved from 264.6 to 1.51 ms in CSC and 268.0 to 1.57 ms in CSR over
the same repetitions.

The direct core consumer still imports five BMIs. Fresh compilation measured
0.182 versus 0.198 s and median consumer-only recompilation measured 0.190
versus 0.192 s. Separate private edit and restore checks in the HDF5 transfer
and core data implementations preserved 15 public BMIs and two consumer
objects in each check. Restoring the sources reproduced the original binary
hashes.
