# Selective I/O and direct access audit

Source audit of baseline `e8c51ce7c3d8c2ded9d1b5f43c1e4d035ea13629` versus family implementation `93c1fa8f6f62a51acfe3f1a1a962701ff6f020e2`. This is a static access-path review, not a timing or runtime qualification. Baseline has no family APIs; comparison is to its existing backed array/mapping contract, not a like-for-like family benchmark. No tracked files changed.

| MuData open | Reads root attributes and modality order, not modality matrices (`src/mudata.cpp:826-847`). Modality and global numeric/map access return rooted backed descriptors (`:585-597`). |
| MuData view / slice | `view()` reads and converts both full axis maps for every modality to retained uint64 vectors (`:360-361,669-681`); temporary decoded source arrays and resulting vectors can coexist. `slice()` resolves selectors and reads selected rows of each map (`:363-372,683-702`); physical chunks can be larger. Nested view slices project retained maps (`:759-775`). Label selectors can require index reads. Matrices remain backed. `read()` is explicit materialization. |
| TreeData open / data | Open inspects root and scalar configuration; embedded AnnData is a rooted backed view (`src/treedata_io.cpp:594-616,639-640`). It does not read tree payload or X at open. |

## Mapping and pointer contract

`BackedStore::anndata(root)` uses a rooted backend that forwards `map_numeric`, numeric transfers, and physical paths (`src/store.cpp:54-73,89-90,108,325-340`). Consequently nested MuData modalities, TreeData's embedded AnnData, and SpatialData tables retain `BackedAnnDataView::x()/layer()` descriptors (`src/backed.cpp:338-345`), and SpatialData raster levels and MuData maps use raw `BackedArray` descriptors. In each case caller-buffer `read_into` is available; full eligible physical arrays can call `map_readonly()`. Family owners retain sessions; explicit close invalidates backed descriptors, while the returned `MappedArray` independently owns the mapping. A pointer from `data()` or dtype-checked `unsafe_data<T>()` is borrowed from that owner and is valid while the mapping owner survives; typed access is the documented Linux/Clang extension, not a C++ object-lifetime guarantee (`src/anndatapp.backed.cppm:117-139,153-172,377-378`; `docs/storage.md:72`).

Mapping is explicit: only full untransformed dense physical arrays map; selection or sparse group and ineligible backend storage return an error, never an allocating read (`src/backed_array.cpp:1048-1056`). HDF5 requires allocated native-order, contiguous, unfiltered, nonexternal data in a regular SEC2 file and uses `PROT_READ` `MAP_SHARED` with a duplicated file descriptor (`src/backed_hdf5.cpp:1383-1438`). Zarr maps only its eligible directly readable native raw chunk as `PROT_READ` `MAP_PRIVATE` (`src/backed_zarr.cpp:348-361`). These are OS demand-paged mappings; HDF5 full validation of bool values scans the mapping, which faults pages (`src/backed_hdf5.cpp:1434-1437`). Compressed, encoded, multichunk and incompatible endian data are not presumed mappable.

Sparse logical `BackedArray::map_readonly()` rejects the group. The existing logical backed array offers sparse `read_into` and transfer APIs; it does not expose a direct values/indices/offsets mapping accessor. The new generic `BackedStore::array` can independently address each physical dense child (`data`, `indices`, `indptr`) by its known absolute path and individually map eligible buffers; this requires opening/accessing the generic physical store separately because family owners do not expose their store. These pointers describe unselected stored buffers, not a selected/rebased sparse view. No new sparse representation is needed. This is a baseline limitation of logical sparse mapping, not a demonstrated regression; generic raw child access is new (`src/anndatapp.backed.cppm:153-172,379-403`; `src/store.cpp:114-123`). No end-to-end nested or sparse mmap runtime reproduction was performed in this audit.

The baseline and reviewed code both provide `MappedArray`, `map_readonly`, and backed X descriptors; their `map_readonly` implementation is unchanged by the compared commits. The change to `src/backed_array.cpp` propagates the new raw-array flag; `RootBackend` forwards mapping without materialization. This supports source-level path continuity, not proof of platform runtime behavior. Follow-up evidence should focus on rooted eligible mapping and physical sparse children if runtime qualification is needed, and on measured axis-name and scalar-tree costs if these inspection workloads matter.

## Bounded runtime verification

A separate verifier exercised the unchanged reviewed implementation on Linux using small uncompressed native-endian fixtures. A dense H5MU modality was accessed through `open_h5mu(...).modality("rna").x().map_readonly()` and its typed `MappedArray::unsafe_data<float>()` pointer. `/proc/self/maps` placed the pointer in a read-only shared file mapping; values remained accessible while the mapping owner survived after the backed handles left scope, and file size/mtime remained unchanged.

A selected dense array rejected mapping with `non_contiguous`. A logical CSR X rejected mapping with `unsupported_layout`. A separately opened generic HDF5 BackedStore mapped `/X/data`, `/X/indices` and `/X/indptr` individually, and the typed pointers yielded the expected values in read-only file mappings. Numerical data access in these checks did not call `read()` or `copy()`.

These checks establish the exercised HDF5 mapping paths, including the rooted modality and physical sparse components. Other families, Zarr layouts, compression modes and mapping lifetimes still need their own representative coverage; the static forwarding analysis alone does not establish runtime qualification for every combination. No timing or page-fault/RSS campaign was performed. Raw source, build recipe and output are preserved in the primary repository under `build/format-family-qualification-2026-11-14/selective-io-fast-path-audit/runtime/`.

The runtime verifier did not trace system calls or page faults, so these checks do not establish that container opening reads no unrelated metadata or file pages. Load-only-what-is-requested still requires direct I/O-range evidence for each relevant workload.

## Repair branch update (2026-11-15)

The access rows above describe the preserved 2026-11-14 implementation and remain historical evidence for that revision. The current `codex/format-family-repairs` diff changes these paths:

- **MuData:** `view()` and positional `slice()` capture map descriptors and revisions without reading map payloads. First access reads the requested modality-axis map and caches it for that view; selected maps are read when needed. The cached `MuMapView` storage lasts with its originating view. A changed map revision or invalidated structural descriptor makes the view stale. Matrix payload remains backed.
- **AnnDataSet:** open still reads the manifest references and opens every linked component, checking missing components, axis sizes, and X presence, but no longer compares all axis names. `validate()` performs the full index comparison; selected-axis requirements and label selection read names only when needed. Dense and sparse `read_x_into` paths preflight all selected segments before writing caller buffers. This is metadata access and transfer preflight, not a claim that opening avoids component metadata or all backend reads.
- **TreeData:** grouped Zarr reads reject unrecognized tree children. For scalar JSON, names scanning still reads the whole indivisible string, but it scans member structure without building all Trees; keyed lookup decodes only the requested member. The scalar bytes and a decoded-tree cache are not retained between calls. Explicit selected materialization still must decode the scalar collection.
- **SpatialData:** polygon construction checks offset rank/type/count/sentinel relationships before inferring geometry types. Owner validation delegates through the view, whose full checks include nested AnnData tables; known capability, validation, and budget failures are preflighted before destination creation/truncation. Native categorical code widths remain unchanged in AnnData++, while Parquet categorical indices are emitted as Arrow int64. When GeoParquet metadata establishes shape kind, empty/ranged shape reads do not probe an unrelated first geometry; incomplete WKB metadata may still require a first-row probe.
- **Shared backed arrays:** `content_revision()` is an equality-comparable uint64 change token, not an operation count or success state. Writes advance it before potentially partial transfers so retained views can notice possible map changes after a failed write. `ArrayView::copy_buffer_bytes()` accounts result buffers and peak sparse-index staging without copying the numerical result.

The [repair validation record](format-family-repair-validation.md) records the final passing matrix, the repeated revised-path mmap checks and the completed bounded sparse screen. It reports timing boundaries and missing instrumentation explicitly; no general speed or reduced-I/O claim is established. Broader access-range coverage remains unmeasured.

The repaired installed consumer repeated the rooted H5MU and physical CSR mmap checks successfully. The [repair validation record](format-family-repair-validation.md) records nine passing configurations, private-rebuild isolation and the one-window sparse screen, including incomplete baseline collection timings and the collection subset-read cost flagged for follow-up.
